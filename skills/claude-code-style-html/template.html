方案 A · 组件内 useEffect + setTimeout

export function TaskSearch() {
  const [draft, setDraft] = useState('');
  const [query, setQuery] = useState('');

  useEffect(() => {
    const id = setTimeout(() => setQuery(draft), 300);
    return () => clearTimeout(id);
  }, [draft]);

  const { data } = useTasks({ search: query });
  return <input value={draft} onChange={e => setDraft(e.target.value)} />;
}

Con

方案 B · 自定义 useDebounce Hook

// src/hooks/useDebounce.ts
export function useDebounce<T>(value: T, ms = 300): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), ms);
    return () => clearTimeout(id);
  }, [value, ms]);
  return debounced;
}
包体积: +0.2 kb 可测试性: 高 复用性: 高 SSR 安全: 是
推荐方案 B

项目已有三处手写防抖逻辑（任务过滤、命令面板、成员选择器），抽取一个共享 Hook 消除了重复，且不引入新依赖。

07 · 研究与学习

原理
代码

一致性哈希（Consistent Hashing）是一种分布式哈希方案，当节点增减时只有少量键需要重新映射。广泛用于缓存分片、数据分区和负载均衡。

TL;DR — 把哈希空间想象成一个环，节点和数据都映射到环上。数据沿顺时针方向找到最近的节点。加减节点只影响环上一小段数据。
哈希环是怎么工作的？

想象一个 0 到 2^32-1 的圆环。每个节点通过哈希映射到环上的某个位置。数据键也通过哈希映射到环上，然后沿顺时针方向找到第一个节点。

什么是虚拟节点？

物理节点在环上映射多个位置（虚拟节点），让数据分布更均匀。节点故障时，其虚拟节点散落在环上，负载被均匀分摊到剩余节点。

为什么比简单取模好？

取模哈希在节点变化时几乎所有键都要重新映射（约 N/N+1）。一致性哈希只有约 1/N 的键需要迁移，大幅降低了数据搬迁成本。

class ConsistentHash {
  private ring: Map<number, string> = new Map();
  private sorted: number[] = [];

  addNode(node: string, replicas = 150) {
    for (let i = 0; i < replicas; i++) {
      const hash = this.hash(`${node}:${i}`);
      this.ring.set(hash, node);
      this.sorted.push(hash);
    }
    this.sorted.sort((a, b) => a - b);
  }

  getNode(key: string): string {
    const h = this.hash(key);
    const idx = this.bisect(this.sorted, h);
    return this.ring.get(this.sorted[idx]);
  }
}
